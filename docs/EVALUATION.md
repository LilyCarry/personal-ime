### 2.3 按错键场景分类处理

1. **模糊音场景（达标才开，避免误伤）**：实测 24 条声韵母模糊音触发率全部 `< 7%`，未达到 15% 开启阈值，因此不自动开启，避免引入多余重码。
2. **按键间隔极短的误触场景（结合按键间隔、键位距离与拼音合法性）**：
   - **同键连击（`<80ms`）**：如 PC 旧键盘 `m` 键连击 18 次（`mma`、`zmm`、`youmemiy`），按 `hw_tag: old_kb` 隔离样本，并可直接写死去抖规则过滤第二下；
   - **紧邻非法组合蹭键（`<45ms` 且物理紧邻、不构成合法拼音组合如 `bn`/`fg`/`jk`）**：高频出现后直接固化为过滤规则；
   - **紧邻合法组合（如 `er`/`ui`/`io`）或左右手高速交替**：不硬吞，避免误杀正常打字；
   - **高频重复词句**：针对手机端 43.6% 的非首选率，启用本地 800 字短期记忆队列（`recent_filter.lua`）提升召回。
3. **复杂错拼与省码场景（交由小模型）**：
   - 物理邻键替换（`i->o`, `r->e`, `f->d`）、漏打字母（`yixa`, `cowu`, `shanyxia`）与高省码（18.7%）存在多义性，交由 `noise_simulator.py` 生成训练样本微调小模型，再通过反引号 `` ` `` 按需调用拼音 Trie 约束解码。

## 4. 核心实验结论（可直接用于展示与报告）

1. **端侧小模型必须“按需唤醒”，而非替代常规词库**：原生雾凇在无错全拼上接近 0ms 且准确率极高；Qwen3-0.6B + Trie 在 `clean_full` 上受限于 8105 词表与惩罚预算（44.0%），但在原生输入法束手无策的 **16 条真实翻车用例上救回率达 62.5% Top-1 / 75.0% Top-3**，印证了“99% 常规打字走 Rime + 反引号按需唤醒本地 AI”的架构合理性。
2. **预训练语义先验 + 拼音 Trie 硬约束缺一不可**：29M 模型虽可在纯 CPU INT8 下跑出 `96.1ms`，但无约束自由解码在长简拼上易发散（如 `tsgzx -> 天上广州下`、`changhs -> 常好帅`）；引入 Qwen3-0.6B 预训练先验与 8105 拼音 Trie 硬锁后，真实用例 Top-1 从 37.5% 跃升至 62.5%，`pc_kb` 与 `pure_initials` 均提升约 +10 个百分点。
3. **滞回防抖有效避免规则误开**：在 2,651 条真实日志上，24 条声韵母模糊音规则触发率均低于 7%，规则层自动保持静默不污染候选，转而由连击去抖、800 字短期热词记忆与小模型承接物理误触与高省码需求。
4. **当前实测短板与下一步改进**：当前 LoRA 权重基于通用 LCCC + 合成噪声训练，尚未混入用户近 3 天个人日志做增量续训，因此低频个人专词 `wuson` 仍输出「伍松」而非「雾凇」；后续将 2,651 条个人日志按时间切分做周末增量微调即可定向补齐个人词表。
