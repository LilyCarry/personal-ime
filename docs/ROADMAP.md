# 演进路线与双目标规划（ROADMAP）

为便于迭代开发、模块解耦以及课程/公开展示，本项目后续明确拆分为**两个相对独立的目标**。两者既可以单独交付运行，也可以通过统一的 `user_profile.json` 画像文件衔接，组成“规则层 + 神经层”双引擎系统。

---

## 目标一：硬编码/可解释规则引擎（初次风格识别 + 后续无感切换）

### 1. 目标定位
不依赖重算力神经网络，直接从原始键位序列、拼音对齐与按键时序中提取显式输入习惯，提供**零延迟、完全可解释、用户可控**的键盘级纠错与风格适配。

### 2. 核心流程

1. **冷启动：初次短文打字校准**
   - 用户首次使用时，照着一段专门设计的 100~150 字诊断短文打字（定向覆盖前后鼻音 `an/ang, en/eng, in/ing`、平翘舌 `z/zh, c/ch, s/sh`、边鼻音 `l/n`、复韵母省码以及高频 QWERTY 邻键易错词）。
   - 前端直接采集原始按键、退格轨迹与按键间隔，复用 `analyze_logs.py` 的编辑距离与声韵母对齐逻辑，在 1 秒内输出**个人输入风格体检报告**：
     - 风格画像与标签（如前后鼻音省 `g` 倾向、简拼比例、左右手换序频率、键盘连击检测）；
     - 键位误触热力图与高频错键 Top-K；
     - 推荐开启的模糊音与键盘纠错选项。

2. **交互式诊断与设置面板（可作为独立网页 Demo）**
   - 提供纯前端静态网页（支持手机/PC 现场扫码打开，采用原始拼音敲击模式避免被系统输入法截断原始键码）。
   - 用户查看体检报告后，可直接在设置面板中勾选或自定义声母/韵母替换规则、连击去抖阈值、邻键容错开关，并在页面内即时试打对比纠错前后效果。
   - 桌面端支持将最终规则导出为 Rime `speller/algebra` 补丁写入 `rime_ice.custom.yaml`。

3. **长期使用：无感规则切换与轻量提醒**
   - 日常使用中由 `ime_logger.lua` 后台静默记录击键与改错行为（按 `hw_tag` 区分不同键盘硬件）。
   - 定期在本地统计滑动窗口内的错键/省码分布；当某类习惯持续达到阈值（例如更换键盘后连击消失，或某组模糊音频率显著上升）时，**后台自动调整/切换对应规则配置**。
   - **轻量提醒机制**：规则发生自动切换时，向用户弹出非打扰式提示（说明切换了哪项规则及触发原因），支持一键撤销或进入设置微调，保证系统可控不“自作主张”。

### 3. 交付清单
- [ ] 全音素/错键覆盖诊断短文与前端静态交互网站（含风格报告、热力图、规则开关与实时试打对比）。
- [ ] 统一的 `user_profile.json` 规范与 Rime `speller/algebra` 自动生成器。
- [ ] 本地滑动窗口习惯监测与规则无感切换 + 轻量通知模块。

## 目标二：基于个人习惯的端侧预测与纠错模型（Transformer 后训练）

### 1. 目标定位
规则引擎擅长确定性的键盘/模糊音替换，但无法处理**强依赖上下文语义**的同音/近音错拼（例如连续简拼或错键后存在多个合法中文词）。本目标通过轻量 Transformer 与本地后训练，让输入法真正学习用户的表达风格与纠错偏好，且所有个人数据不出本地。

### 2. 核心技术路线

1. **个人习惯驱动的合成数据增强**
   - 解决单人日常日志量少、直接微调易过拟合与灾难性遗忘的问题。
   - 从真实日志（或目标一导出的 `user_profile.json`）中提取个人错误分布参数，注入 `noise_simulator.py`；
   - 将个人噪声分布叠加到通用中文对话语料（LCCC）上，合成贴合该用户手指习惯的训练样本，并与真实个人日志混合。

2. **双架构本地后训练（周期性空闲训练）**
   - **PC 端路线（Qwen3-0.6B-Base + LoRA 后训练）**：
     - 将按键序列按空格拆分为单字母 token，绕开通用 BPE 词表对拼音残片不敏感的盲区；
     - 底座参数冻结，利用周末或设备空闲时间在用户本地 GPU 上花数分钟完成 LoRA 增量微调（增量权重约 40MB），学习个人高频错拼与表达习惯。
   - **移动端 / 轻量端路线（~29M 自研字级 Transformer）**：
     - 词表精简至 8105 常用汉字 + ASCII + 标点，采用 RMSNorm + RoPE + SwiGLU；
     - INT8 量化后约 29MB，面向手机或无独显设备的离线 CPU 推理。

3. **受限解码与低延迟系统集成**
   - 推理阶段引入**拼音 Trie 容错约束 Beam Search**（`ime_server.py`），将 Transformer 的语义概率分布约束在合法拼音及允许编辑距离内，彻底消除生成幻觉；
   - 通过无黑框 C 扩展 `ime_bridge.dll`（本地 TCP）接入小狼毫 `ai_filter.lua`，服务未启动时 0.1ms 无感回退原生词库。

### 3. 交付清单
- [ ] 一键周期性增量训练流水线 `weekly_update.py`（日志解析 -> 噪声参数更新 -> 增量数据构建 -> LoRA 微调 -> 推理服务热重载）。
- [ ] 系统化评测对比表：原生 Rime vs 29M 字级模型 vs Qwen3-0.6B LoRA（自由解码） vs Qwen3-0.6B LoRA（拼音 Trie 约束解码）的 Top-1 / Top-3 准确率与端到端延迟。
- [ ] 端侧量化导出与跨设备权重同步验证（PC 周末微调 -> 同步至轻量端）。

## 两目标的关系

| 维度 | 目标一：规则引擎 | 目标二：个人预测模型 |
| :--- | :--- | :--- |
| **核心机制** | 编辑距离对齐 + 声韵母统计 + 确定性规则 | Transformer 注意力 + LoRA 后训练 + 拼音 Trie 约束解码 |
| **算力需求** | 极低（纯前端 JS / 本地 CPU 毫秒级） | 消费级 GPU 训练（数分钟），GPU/CPU 推理 |
| **可解释性** | 强（明确展示习惯报告，支持手动开关） | 中（通过受限解码保证输出可控） |
| **擅长场景** | 冷启动体检、固定模糊音、物理连击、邻键单点替换 | 长句上下文消歧、连续简拼/重度错拼恢复、个人用词偏好 |
| **衔接方式** | 导出 `user_profile.json` | 读取 `user_profile.json` 作为冷启动噪声先验，再随日志迭代 |
