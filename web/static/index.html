01 // MOTIVATION · 体验起点与痛点

微信输入法确实很舒服，但输入法这件事，我们想自己掌控

日常使用微信输入法，即便随手敲出一串简拼，它也能顺着语境猜出整句；但正因为输入法最懂你在想什么，闭源商业方案的三大短板才更显棘手。

实测体验：重度简拼下，它的预测确实很聪明

微信输入法真实案例
案例 1 · 个人语言习惯 ni'ge'c'l'l 命中专属口癖，而非泛用词语
1 你个臭乐乐 2 你哥出来了 3 你个出来了
案例 2 · 自造句渐进记忆与省键 同一自造句「签到了快起床」两次输入对比
第 1 次打（效果不如意） qian'd'l'kuai'q'c
1 钱多了快去吃 2 钱到了快去吃 3 前端 4 签到

第 2 次打（更省键直接出） qian'd'l'k'q'c
1 签到了快起床 2 签订了看清楚 3 签到了 4 前端

但是：为什么商业输入法不是终极答案？

三大核心局限
01
输入法极度隐私敏感

聊天记录、账号密码、个人想法全经过输入法；闭源软件的云端联想与遥测机制让人难以彻底放心数据边界。

02
呆板的通用“空间换时间”

面向大众平均习惯构建庞大静态通用词库 + 重型本地模型，靠堆内存和算力覆盖平均人，策略固化且资源开销大。

03
深度定制化程度低

只能粗粒度勾选几个固定模糊音，既看不到自己真实的声韵母偏差统计，也无法用个人专属语料在本地持续训练模型。

核心思考

我们先拆清微信输入法背后的“噪声信道与多级重排”原理，再看如何用开源 Rime 做到又聪明、又轻量、完全属于你。

02 // COMMERCIAL IME ARCHITECTURE · 竞品底层原理解剖

现代智能输入法（如微信输入法）的吞键容错与预测原理

本质是一个噪声信道模型（Noisy Channel Model）：在敲击序列 K 残缺或误触时，联合搜索“最像你说的话”与“最可能这样敲错”的词句。

W* = argmax P(W | Context) × P(K | W)
STEP 01 // INPUT

残缺 / 吞键按键流

xiag 吞键漏打：漏掉后鼻音 n
senm / qian'd'l'k'q'c 平翘舌混淆 / 尾音截断与简拼
niaho 高速连打：左右手相邻换序

同步采集 2D QWERTY 键位落点与击键间隔，输入错误模型 P(K|W)。

STEP 02 // FUZZY LATTICE

模糊拼音格 & 容错搜索

路径 A：xiag -> xiang 补 n · 对应 想/项/像（上下文强匹配）
路径 B：xiag -> xia + g 强行割裂：下个/夏哥（被 Beam 剪枝）
路径 C：邻键 g -> f / h 2D 键距加权，构建 WFST / 容错 Trie 保留 Top-K

不做死板音节切分，边扫按键边联合搜索“拼写容错 + 词句概率”。

STEP 03 // MULTI-TIER LM

多级语言模型打分与重排

L1 本地极速词典 / N-gram< 5 ms
庞大静态通用词库 + 热词缓存，靠“空间换时间”直接命中约 80% 常规高频输入。
L2 端侧轻量神经模型10~30 ms
几十 MB 量化 RNN / Transformer，结合上下文对 Top-K 候选重排与下一词预测。
L3 云端大模型 / 热词补强异步联网
重度错拼或长句简拼时，异步上传上下文至云端拉取联想候选插入前排。

层层加码的通用大底座：省了训练，却把空间和隐私成本转嫁给用户。

STEP 04 // OUTPUT

智能纠错候选输出

1. 想吃什么上下文重排 Top-1
2. 你好呀换序纠错
3. 晚上一起下一词预测

只要语言模型得分足以抵消拼写惩罚，即使敲错或吞键也能精准输出。

商业方案局限 1. 隐私敏感（L3 云端上下文出境顾虑） 2. 呆板空间换时间（L1 通用大词库无法按个人手癖裁剪） 3. 定制化低（不能微调个人声韵母习惯与本地专属语料）
03 // OUR SOLUTION · 基于 RIME 的 PERSONAL-IME

基于 Rime 的个性化输入法：轻巧、开源、且真正懂你

我们不重复造词库轮子，也不靠百兆通用大模型硬扛；而是把开源 Rime（小狼毫 + 雾凇拼音） 与个人习惯驱动结合起来，沉淀出四大核心亮点：

01
开源底座 · 数据自主

基于开源库，零黑盒全本地

立足 Rime 引擎 + 雾凇拼音 + 8105 通用字表 + Qwen3 开源生态，只用 Lua 插件与轻量本地服务增强。所有日志写入前硬拦截敏感数字/邮箱/密钥，数据与模型权重 100% 留在本地。

rime/ · 8105.dict.yaml · Qwen3-0.6B
02
开局冷启动 · 告别盲猜

开局个性化定制规则，不用自己猜习惯

多数人根本不知道自己平时爱把 ong 打成 on 还是混淆 l/r。开局只需敲 3 句测速文本，系统自动与标准拼音对齐并量化成专属 Rime 模糊音补丁。

/play 诊断 -> 24 条标准规则 -> algebra 补丁
03
日常演化 · 越用越准

使用中智能切换，拒绝候选栏变脏

模糊音开多了会出大量重码。日常使用通过 500 条滑动窗口核算每条规则的真实收益（>=15% 开启 / <5% 关闭），习惯一变自动热切换并轻提醒。

rule_updater.py · rule_notify.lua
04
长期沉淀 · 个性化小模型

长期使用自动训练小模型，取代呆板大词库

长期日志积攒了你的真实错键分布与常用语境后，周末空闲本地微调专属小模型（LoRA / 29M），并用拼音 Trie 约束 + 亚毫秒 C 桥接按需接管长简拼纠错。

noise_simulator · LoRA · Trie Beam Search
04 // HIGHLIGHT 1 & 2 · 开局个性化规则定制

不用自己猜习惯：3 句竞速对齐 + 24 条标准 Rime 规则编译

传统输入法只给一堆开关让你自己猜；我们直接采集原始敲击流，经动态规划音节对齐与白名单防幻觉校验，确定性编译为雾凇拼音补丁。

冷启动自动诊断流水线

A
无空格连打 DP 音节对齐（play.js）

允许按平时习惯不按空格直接连敲整句，通过 1~7 字符窗口 + 编辑距离动态规划对齐到参考音节，准确抽取 zhon->zhong、len->ren。

B
DeepSeek 趣味点评 + 白名单防幻觉归一化

DeepSeek 在 24 条标准词表内挑选规则并生成点评；后端 normalize_rule_id 归一化别名并拦截自造规则，无 Key 或超时 >6s 自动切换本地启发式。

C
24 条标准可量化规则（rules_schema.py）

覆盖 7 声母（平翘舌、l=n、l=r、f=h、g=k）、8 韵母（ong=on、前后鼻音）、9 容错（ju=jv、换序 an=na、zh=hz）。

            07 // HIGHLIGHT 4 (PART A) · 长期演化：个性化小模型后训练
            
长期自动训练小模型：个人物理噪声拟合 + 单字母分词破壁

按三行错位坐标 (0.0 / 0.35 / 0.85) 以 1/dist^2 采样邻键替按，叠加换序/吞键/蹭键。

Beam Search 打分函数与安全边界

              

                Score = logP_LM(token | ctx, keys) + 4.2 * ep - sum(penalty)
              

              
    
                
  • ep 进度奖励（4.2 / 键）：鼓励候选词消费完所有按键，避免中途截断。
