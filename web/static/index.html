现实矛盾 · 点击逐条揭开痛点
01

输入法是极度隐私敏感的入口

聊天内容、账号密码、搜索想法全经过输入法；闭源客户端的云端联想与遥测，让人很难完全放心数据流向。

02

呆板的通用“空间换时间”

面向全网平均习惯堆砌庞大静态词库和重型本地模型，策略固化、资源开销大，无法按个人习惯裁剪。

03

深度定制化程度低

只能勾几个粗糙的固定模糊音，既看不见自己真实的声韵母偏差统计，也没法拿个人语料在本地训练专属模型。

不靠云端、不靠百兆静态大词库，点击下方卡片依次展开从第 1 分钟到第 100 天的四项核心设计。

02 开局冷启动 · 告别盲猜

开局个性化定制规则，不用自己猜习惯

很多人说不清自己是 l=n 还是 ong=on。开局盲敲 3 句测速文本，系统自动与标准拼音对齐并编译出专属 Rime 补丁。

03 日常演化 · 防抖防脏

使用中智能切换，拒绝候选栏越用越脏

日常敲击通过 500 条滑动窗口核算每条规则真实收益（>=15% 开启 / <5% 自动关闭），换键盘也能无感切换并轻提示 3 次。

04 长期沉淀 · 端侧小模型

长期使用自动训练个人小模型

用个人脱敏日志校准物理噪声分布，周末本地自动增量微调 LoRA / 29M 模型，配合 拼音 Trie 约束与 C 桥接按需接管重度简拼纠错。

04 // 怎么不用猜就配好 Rime 规则？

无空格 DP 对齐 + 24 条白名单防幻觉 -> 确定性 Rime 编译

点击左侧逐步展开防误判与防幻觉设计，在右侧点击任意规则 ID 查看实时编译出的雾凇配置补丁。

A

无空格连打 DP 音节对齐（play.js）

不用刻意敲空格分隔音节；前端以 1~7 字符窗口 + 编辑距离做轻量动态规划，把整句 zhonguolenmin 对齐拆回 zhon|guo|len|min。

B

DeepSeek 点评 + 白名单归一化防幻觉

大模型写正则容易语法翻车；后端限制它只能在 24 条标准 ID 中选，经 normalize_rule_id 统一别名并拦截幻觉 ID；无 Key 或超时 >6s 自动切换本地兜底。

C

24 条标准离散规则词表（rules_schema.py）

涵盖 7 声母（平翘舌、l=n、l=r、f=h、g=k）、8 韵母（ong=on、前后鼻音）、9 容错（ju=jv、换序 an=na、zh=hz）。

              07 // 个人日志不够多、大模型又切碎拼音怎么办？
            

            
物理噪声参数化合成语料 + 单字母分词破除 BPE 盲区

            

              真实个人日志只有几百条，用它校准物理噪声模拟器批量合成语料，并通过空格拆成单字母让注意力真正对齐拼音。

              08 // 怎么做到不乱造字且零阻塞？
            

            
拼音 Trie 硬约束防幻觉 + Winsock2 亚毫秒按需桥接小狼毫

            

              依次点亮下方 4 个节点：平时敲击 0ms 走雾凇原生，末尾敲 ' 按需触发本地推理，并用 8105 汉字读音 Trie 锁死读音边界。
