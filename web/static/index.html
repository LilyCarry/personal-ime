01 // MOTIVATION · 为什么还要重做一个输入法？

微信输入法确实好用，但输入法这件事，我们想自己掌控

日常用微信输入法很顺手，它的长句与模糊预测足够聪明；但越高频使用越发现三个绕不开的瓶颈：隐私敏感、策略呆板（时间换空间）、几乎无法按个人手癖深度定制。

体验起点：微信输入法的预测确实很舒服

聪明但不属于你

即便随手连敲或少打几个键，微信输入法也能顺着语境猜出你想说的话——这是我们真正欣赏的“智能感”。

但是：为什么它不是终极答案？

三大核心痛点
01
输入法极度隐私敏感

聊天记录、账号密码、个人想法全经过输入法；闭源软件 + 云端联想让人难以彻底放心。

02
呆板的“时间换空间”

依赖通用重型词库与固定云端/本地大模型算力堆叠，策略僵硬、内存和响应开销大。

03
定制化程度低

只能全局开几个粗糙模糊音，无法针对你独有的省键节奏、错键分布和常聊语境持续演化。

02 // SOLUTION & HIGHLIGHTS · 基于 RIME 的个性化输入法

于是我们基于 Rime，打造真正懂你的 Personal-IME

不从零重写输入法框架，而是以开源 Rime（小狼毫 + 雾凇拼音） 为底座，把“开局冷启动定制 + 日常智能切换 + 长期小模型演化”全部留在本地。

01
开源底座 · 数据自主

基于开源库，零黑盒全本地

立足 Rime 引擎 + 雾凇拼音 + 8105 通用字表 + Qwen3 开源生态，只用 Lua 插件与轻量本地服务增强，敏感内容（数字/邮箱/密钥）写入前直接拦截。

rime/ · 8105.dict.yaml · Qwen3-0.6B
02
开局冷启动 · 告别盲猜

开局个性化定制规则，不用自己猜习惯

大多数人其实说不清自己是 l=n 还是 ong=on。只需敲 3 句测速文本，系统自动对比参考拼音与原始击键，量化生成 Rime 补丁。

/play 诊断 -> 24 条标准规则 -> algebra 补丁
03
日常演化 · 越用越准

使用中智能切换，拒绝词库越用越脏

日常敲击通过滑动窗口统计每条规则的真实收益（15% 开启 / <5% 自动关闭），换键盘或习惯变了也能无感切换并轻提示。

rule_updater.py · rule_notify.lua
04
长期沉淀 · 端侧智能

长期使用自动训练个人小模型

随个人日志积累，周末空闲本地微调轻量模型（LoRA / 29M），配合拼音 Trie 容错约束与亚毫秒 C 桥接，既懂你的错键习惯又不会乱造字。

noise_simulator · LoRA · Trie Beam Search
03 // HIGHLIGHT 1 & 2 · 开局个性化规则定制

不用自己猜习惯：3 句竞速自动诊断 + 24 条 Rime 规则编译

传统输入法让你对着几十个模糊音开关发呆“我到底要不要开？”——我们直接把你在真实敲击中暴露的细微习惯，确定性地编译成可开关的 Rime 配置。

自动诊断流水线（为什么不用手猜、也不会有幻觉？）

A
无空格连打 DP 音节对齐（play.js）

允许按平时习惯不敲空格直接连打，用动态规划（1~7 字符窗口 + 编辑距离）把按键串对齐到每个汉字的标准拼音，精准捕捉 zhon->zhong、len->ren。

B
DeepSeek 点评 + 白名单防幻觉归一化

DeepSeek 生成趣味点评并推荐规则 ID；后端经 normalize_rule_id 将别名归一化，严禁大模型自造语法；无 Key 或超时 >6s 自动切换本地启发式兜底。

C
24 条标准离散规则（rules_schema.py）

覆盖 7 声母（平翘舌、l=n、l=r、f=h、g=k）、8 韵母（ong=on、前后鼻音）、9 容错（ju=jv、换序 an=na、zh=hz）。

            06 // HIGHLIGHT 4 (PART A) · 长期演化：个性化小模型后训练
            
长期自动训练小模型：真实物理噪声拟合 + 单字母分词破壁

            

              规则解决固定手癖，但遇到“既简拼又误触”且依赖上下文的情况（如 wishi -> 我是、paoshibnie -> 跑识别），需要利用个人日志参数化合成语料并周末本地微调轻量模型。
            

          


          

            

              
1. 从个人习惯参数化合成训练对（noise_simulator.py）

              

                

                  层 1 · jieba 词级节奏
                  
按词决定全拼(35%) / 纯首字母(28%) / 前重后轻半截(25%) / 混打(12%)，而非逐字随机。

                

                

                  层 2 · 21 种发音省力截断
                  
优先截断后鼻音 g 与复韵母尾音（iang->ia/ian, ong->on, uo->o）。

                

                

                  层 3 · 错位 QWERTY 物理误触
                  
按三行错位坐标 (0.0 / 0.35 / 0.85) 以 1/dist^2 采样邻键替按，叠加换序/吞键/蹭键。

                

              


              

                

                  真实翻车案例合成演化演示
                  

                

                

              

            


            

              
2. 单字母分词破除 BPE 盲区 + 双端小模型路线

              

                

                  直接喂原始串（BPE 盲区）
                  wmxqcf -> ["wm", "xq", "cf"]
                  
BPE 把按键合并成英文子词，模型看不到声母边界。

                

                

                  单字母空格拆分
                  "<w m x q c f>" -> ["w","m","x","q","c","f"]
                  
注意力机制直接对齐“上文 28 字 + 逐键输入序列”。

                

              


              

                

                  

                    PC 端周末微调：Qwen3-0.6B LoRA
                    r=16, alpha=32
                  

                  
仅对 <tgt> 后目标汉字算损失，bf16 + 梯度检查点，个人 PC 周末空闲即可本地后训练更新。

                

                

                  

                    移动端端侧模型：自研 ~29M Transformer
                    INT8 约 29MB
                  

                  
8 层 8 头（RMSNorm + RoPE + SwiGLU + Weight Tying），词表压缩至 ~8.5k，可离线跑在手机 CPU。

                

              

            

          

        


        
        

          

            07 // HIGHLIGHT 4 (PART B) · 拼音 TRIE 约束与亚毫秒 RIME 桥接
            
不放纵小模型乱造字：拼音 Trie 容错约束 + 零黑框接入小狼毫

            

              不是用“时间换空间”硬跑全词表，而是按需触发 + 8105 汉字读音 Trie 剪枝 + Winsock2 亚毫秒 C 桥接，既能容忍误触又守住读音底线。

精确匹配 (woshi)0.0

                
声母/前缀缩写 (w / wo)0.9

                
相邻换序 (kaui -> kuai)2.8

                
缺介母/尾键 (yixa -> yixia)3.0

                
翘舌首写反 (hs -> sh)3.0

                
邻键替按/蹭键 (wishi / bnie)3.2

              

            


            

              
Beam Search 打分函数与安全边界

              

                Score = logP_LM(token | ctx, keys) + 4.2 * ep - sum(penalty)
              

              
    
                
  • ep 进度奖励（4.2 / 键）：鼓励候选词消费完所有按键，避免中途截断。
    • 
                
  • 硬性惩罚上限：单步 DFS 容错代价 <= 4.5、整句累计代价 <= 7.0，既能同时救回两处错键，又绝不偏离读音乱出字。
