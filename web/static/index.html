为什么做 Personal-IME：从真实翻车日志到隐私优先定制

03 // GOAL 1 (PART A): COLD-START & DETERMINISTIC RIME COMPILER

目标一原理（上）：冷启动识别 -> 白名单防幻觉 -> Rime 正则编译

为什么不让大模型直接生成 Rime 配置文件？因为 LLM 容易编造非法正则语法。本项目将 DeepSeek 严格限制在 24 条标准离散规则白名单内选 ID，再由确定性编译器输出 YAML 补丁。

1. 三层处理流水线（play.js + deepseek_client.py）

A
无空格连打 DP 音节对齐

前端支持不按空格直接连敲整句，通过动态规划（音节窗口 1~7 字符 + 编辑距离）将连续按键切分对齐到参考拼音，准确抽取出 zhon->zhong、len->ren。

B
DeepSeek JSON Mode + 别名归一化 + 6s 降级

Prompt 注入 24 条标准词表；返回后经 normalize_rule_id 将 zh=z/u=v 归一化，直接丢弃任何幻觉 ID；无 Key 或超时 >6s 自动切换本地启发式规则推荐。

C
可量化规则词表（profiler/rules_schema.py）

涵盖 7 条声母（平翘舌、l=n、l=r、f=h、g=k）、8 条韵母（ong=on、前后鼻音）、9 条容错（ju=jv、换序 an=na、zh=hz）。

            05 // GOAL 2 (PART A): NOISE SIMULATOR & CHAR-LEVEL TOKENIZATION
            
目标二原理（上）：物理噪声模拟与单字母分词破壁

            

              真实个人脏日志只有几百条，不足以从头微调大模型。本项目通过 noise_simulator.py 在 LCCC 语料上按真实物理分布合成 45 万条训练对，并解决大模型 BPE 切碎拼音的痛点。
            

          


          

            

              
1. 词级混合 + 物理 QWERTY 噪声（noise_simulator.py）

              

                

                  层 1 · jieba 词级模式
                  
按词决策而非逐字随机：35% 全拼 / 28% 纯首字母 / 25% 前重后轻半截 / 12% 混打，还原人类以词为单位的省力节奏。

                

                

                  层 2 · 21 种发音省力截断
                  
优先截断后鼻音 g 与复韵母尾音（iang->ia/ian, ong->on, uo->o）及翘舌 zh/ch/sh->z/c/s。

                

                

                  层 3 · 二维错位键盘采样
                  
三行按键按真实错位坐标 (0.0 / 0.35 / 0.85) 建模，邻键替按按距离平方反比 1/dist^2（dist <= 1.55）加权，叠加换序/吞键/蹭键。

2. 为什么必须用空格拆成“单字母 Token”？

              

                

                  直接输入原始串（BPE 盲区）
                  wmxqcf -> ["wm", "xq", "cf"]
                  
通用 BPE 把连续按键合并成罕见英文子词，模型看不到单个声母边界！

                

                

                  本项目单字母拆分输入
                  "<w m x q c f>" -> ["w","m","x","q","c","f"]
                  
每个按键独立成 Token，注意力机制直接对齐“上文汉字 + 逐键拼音”。

                

              


              

                

                  

                    PC 端路线：Qwen3-0.6B LoRA
                    r=16, alpha=32
                  

                  
全线性层挂载 LoRA（q/k/v/o/gate/up/down_proj），bf16 + 梯度检查点，仅针对 <tgt> 后汉字计算交叉熵，周末空闲 60k 样本即可更新个人权重。

                

                

                  

                    移动端路线：自研 ~29M 字级 Transformer
                    INT8 约 29MB
                  

                  
8 层 8 头（d_model=512, d_ff=1408），RMSNorm + RoPE + SwiGLU + SDPA + Weight Tying，词表压缩至 ~8.5k（8105 常用字+ASCII+标点），支持手机 CPU 离线推理。

                

              

            

          

        


        
        

          

            06 // GOAL 2 (PART B): PINYIN-TRIE CONSTRAINED DECODING & RIME BRIDGE
            
目标二原理（下）：拼音 Trie 容错约束解码与 Rime 亚毫秒桥接

            

              纯自回归解码有可能写出“语境通顺但读音完全不对”的幻觉词。我们在推理期将 8105 汉字读音 Trie 与 QWERTY 容错代价图嵌入 Beam Search，并通过 C DLL 零黑框接入小狼毫。
            

          


          

            
          


          

            

              
音节容错变体代价表（build_typo_variants）

              

                
精确匹配 (woshi)0.0

                
声母/前缀缩写 (w / wo)0.9

                
相邻换序 (kaui -> kuai)2.8

                
缺介母/尾键 (yixa -> yixia)3.0

                
翘舌首写反 (hs -> sh)3.0

                
邻键替按/蹭键 (wishi / bnie)3.2

              

            


            

              
Beam Search 综合打分函数与剪枝边界

              

                Score = logP_LM(token | ctx, keys) + 4.2 * ep - sum(penalty)
              

              
    
                
  • ep 进度奖励（4.2 / 键）：鼓励候选词消费完所有按键，避免提前停在短词。
    • 
                
  • 双层惩罚剪枝：单步 DFS 路径代价上限 <= 4.5，整句累计错键惩罚上限 <= 7.0，既能同时容忍 2 处错拼，又防止无底线偏离读音。
